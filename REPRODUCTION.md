# Reproduction Record

## Release Status

This directory is the source of the proof artifact. A public release must identify a
specific Git commit or an annotated tag. Do not cite a moving branch such as the main
branch in a paper or submission.

The reproducibility command is:

    bash scripts/verify.sh --regenerate

It verifies every published binary digest, verifies the two safety certificates, runs the
reference rules tests, exhaustively verifies the colour-conjugate rule book, regenerates
the deterministic artifacts, and compares the regenerated bytes with the published files.
The required success markers are in expected-output.txt.

## Environment

The original reference run reported CPython 3.10, GCC 11.4, C99 with -O2, and x86-64
Linux. The exact distribution release was not recorded, so this is not a clean-room
record. GitHub Actions runs the verification on ubuntu-24.04 with CPython 3.12 and
records the command output for every public commit.

## Independent Reproduction

Status: not yet completed.

Before a non-anonymous submission, obtain a run by someone who did not prepare the
artifact. Record the artifact commit or tag, operating-system release, gcc --version,
python3 --version, the exact command above, its exit status, and the complete output in
this file or a tagged GitHub release. A different SHA-256 digest means byte-for-byte
regeneration was not reproduced; it does not by itself refute the theorem if the newly
generated certificate passes src/certify.c.
